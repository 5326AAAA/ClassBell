# 原生作业 AI 学习辅助：接入讨论

状态：方案核对，尚未加入 APK。用户希望手动选择题目或功能，由 AI 生成参考解答与讲解。

## 已核对的现状

ClassBell 的 `HomeworkItem` 保存标题、状态、截止时间及详情 URL，没有题干、选项和答案结构。`HomeworkApi` 读取列表并从部分详情页补截止时间；原生作业列表目前把查看/提交交给 `OfficialPageActivity`。需要先增加原生题目读取与展示层。

`chaoxingStudy-Helper/main.py` 的作业流程通过 Selenium 读取网页题干与选项，调用模型再点击网页。它针对的题型和选项有限，提示词要求只返回选项字母，未设计详细讲解或用户审核。这能提供部分 DOM 线索，但不能直接作为 Android 原生作业模块。

本地 Doraemon 参考副本的 `HtmlParser.kt` 展示了 HTML 转原生详情的方向，但只取首个题型、题干和问题 ID，提交题型固定，不能覆盖所有作业。

PassChaoxing 文档列出了作业详情接口，但没有完整题目 schema 和有效响应样例。本次没有调用真实作业接口验证其返回结构，不能仅按接口名直接接入。

## 建议的原生流程

进入作业 → 选择一道或勾选数道题 → 选择「提示」「分步讲解」「参考答案」→ 显示生成结果 → 用户核对、修改、复制或采用到本机草稿。

默认由用户触发；可选在打开当前题目时自动生成讲解。列表刷新只更新作业信息，不触发全列表模型请求。讲解和参考答案分开呈现，生成进度、停止按钮与失败重试放在同一张 AI 卡片内。

第一阶段处理常见文字题，保留单选、多选、判断、填空与简答的题型信息。解析时保留公式、上下标、表格和图片引用；只用网页 `.text()` 会丢失这些内容。原生解析失败时，提供手动粘贴或用户选取截图的补充入口，识别后先让用户校正题干与选项。

## 模块与接口

1. `HomeworkDetailSource`：在当前账号中读取详情与必要图片，提供可验证的活动/作业身份。
2. `HomeworkQuestion`：题型、题干、稳定题目 ID、选项 ID、公式、图片和内容摘要。模型输出映射到实际选项 ID，避免选项顺序变化后误用字母。
3. `HomeworkAiClient`：可配置的 `baseUrl + model + key`，独立请求与可取消任务。
4. 原生题目页：题目、提示、讲解、参考答案和本机草稿，保留用户核对过程。

若现有 CLIProxyAPI 提供兼容接口，可先沿用它，验证选定模型的文字、图片及结构化输出能力。参考脚本分别使用 Ollama HTTP 接口和 Qwen SDK；具体模型是否支持视觉与结构化结果需要单独验证。无结构化输出时回退为可阅读文本，不据此自动填写。

手机的 `127.0.0.1` 指手机自身，连接电脑上的服务需要手机可达的服务地址。发布版优先使用带鉴权的 HTTPS 入口；调试连接另行配置，不在 APK 内写死服务密钥。

AI 请求只包含当前选定题目的内容和必要图片。学习通会话、Cookie、账号资料、带签名 URL 与隐藏表单留在学习通读取模块。图片先由学习通客户端获取必要内容，再交给视觉模型；不照搬参考脚本的外部图床流程。

AI 配置可沿用 Android Keystore 加密思路，但使用独立存储与清理生命周期。返回结果按账号、作业、题目内容版本和模型配置校验，防止切换账号或题目后显示旧回答。支持停止、超时、逐题重试和隔离缓存。
