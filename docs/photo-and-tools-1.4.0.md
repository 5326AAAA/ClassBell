# v1.4.0：拍照恢复、多账号与新工具

## 拍照签到

进入「签到中心 → 选择关联账号」，勾选属于这门课程的已授权账号，点击「核对所选账号的要求」。为每个需要照片的账号分别选图，在确认页核对账号和照片，然后提交。最多三个拍照账号同时上传；单个账号出错不会中断其他账号。

每个账号使用独立会话、照片文件和提交记录。完成本次处理后清除临时照片。已确认成功的账号不会重复提交。照片上传成功只表示文件传输完成，最终签到状态单独显示。

如果服务器回复未知，先点「刷新所选账号的签到结果」。只有返回记录匹配当前活动和账号，并明确显示未签到，才恢复该账号的选图和手动提交入口；正在发送或已经确认成功的账号保持锁定。单账号拍照页面使用相同规则。应用不会自动反复上传照片。

官方页面准备放在照片上传之前；遇到额外验证时先停止，不上传照片。上传前依然检查活动是否有效、身份与签到类型是否匹配。

## 新功能

- 「使用帮助 → 检查更新」：原生显示当前版本、GitHub 最新正式版、更新说明及安装包入口。手动检查，不带学习通 Cookie。新版 APK 由浏览器下载，用户手动覆盖安装；不自动安装或降级。
- 「作业 → 作业截止日历」：预览当前账号缓存中有截止时间的待交作业，排除已交、过期及手动完成的项目，保存为 `.ics` 文件。可以附带截止前 30 分钟的日历提醒。无需日历或全部文件权限，提醒由导入后的日历应用处理。课程内打开时限定为当前课程范围。文件不包含作业签名 URL、会话或原始账号 ID。

日历是导出时的数据快照。完成作业或修改截止时间后，需要重新导出并核对日历中的旧事件；不同日历应用的导入与去重行为可能不同。

## 日志结论与验收边界

用户提供日志的 2026-11-26 记录显示：12:12:39 照片上传已确认，随后签到返回一段未识别的 21 字符文本，查询返回当前账号未签到。旧版此时仍保留提交锁，这是本轮修复的确定缺陷。

日志只保留响应长度、结构与摘要，没有原始的 21 字符回复，因此不能确认学校服务器拒绝的具体文本原因。本轮增加安全关键词标记，继续保留不记录原始回复、照片、Cookie 和签名的日志约束。不会把上传成功作为签到成功。

自动化测试使用合成账号和响应。真实学校活动是否接受某张照片，需要在有效活动中验证；ADB 未连接时不记录为真机验收成功。
