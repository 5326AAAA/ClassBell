## 发现与修复

1. **已交作业多层导航**：真实流程为 task-work 预览 → selectWorkQuestionYiPiYue 报告 → 完整题页。初版只识别直接字面量链接，停在预览；补齐页面提供的固定字符串、隐藏输入绑定和常量拼接。无障碍显示参数使用页面声明的默认值，不运行 JS。
2. **手机页面结构**：完整页使用 singleQuesId / qtContent / qtDetail，而参考项目主要是 questionLi / mark_name / answerBg。新增手机题干、选项、类型解析，排除 stuAnswerContent、教师答案和 wrIcon。作答页使用 workWrap / titType，也已适配。
3. **未交作业选错报告**：同页可能同时包含不可访问的旧报告入口和“开始答题”。显示明确进入按钮时先要求用户选择；获得许可后使用页面提供的 doHomeWork 地址。不会因为刷新列表或后台操作就开始作业。服务器明确无权限时给出错误，不显示为零道题。
4. **题图403**：初版图片请求缺少与页面一致的来源及浏览器请求头。真机对照同一图片加入这些头后返回200；正式保存流程现带移动浏览器 User-Agent 和官方来源站点 Referer，Referer不带作业签名参数。
5. **退出崩溃**：Android 17 关闭空闲TLS连接可能写入 close_notify，原来的主线程连接池清理触发 NetworkOnMainThreadException。取消和关闭清理改为后台执行；真实下载后等待页面销毁的复测通过。

最初的0题、图片403、退出崩溃以及未交报告无权限均记录为失败，未把“诊断采集OK”计为功能验收。未交场景曾在请求失败前留下上一场景的快照；已标记并保留原件，随后测试增加runId核验。最终只以上表三个新场景的匹配结果计入通过。
